# Spark session optimization for yarn mode

We have seen how to optimize a spark session in local mode, in this tutorial, we will learn how to optimize a spark session in yarn mode.

## Basic executor resource configuration

A spark session resource in yarn cluster has two parts:
- driver
- worker

The `Spark Driver` acts as the brain and coordinator, while `Spark Executors` act as the muscle performing parallel computations.

### The spark driver

In a yarn cluster, the spark driver role is
- Converts Code to DAG / Task Stages
- Requests Containers from YARN RM
- Schedules Tasks to Executor Slots
- Collects Results / Action Data


The locality of spark driver is quite different based on `YARN Deploy Modes`:

- `client Mode`: Driver runs outside the YARN cluster on the client node/gateway machine where the job was launched. `If the client disconnects or network drops, the application dies.` (e.g. pyspark in notebook, sparklyr in Rstudio)
- `cluster Mode`: Driver runs inside a YARN ApplicationMaster container managed by YARN on one of the cluster worker nodes. Essential for long-running batch jobs in production. (e.g. spark-submit)
